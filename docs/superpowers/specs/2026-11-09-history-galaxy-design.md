# 历史星河设计规格

## 项目目标

《历史星河》是一款全屏 3D 互动网页作品，以唐、宋、元、明、清至中国近代史为主轴。用户在一条横贯星空的历史时间轴上自由航行，观察不同影响力的历史事件光点，拖拽光点改变其空间构图，并通过点击进入人物与故事叙事。

作品的第一目标是可玩性与沉浸感，第二目标是让用户在不阅读操作说明的情况下理解时间顺序、朝代分区和事件影响力。页面不是营销落地页，首屏直接进入可交互的 3D 场景。

## 体验范围

- 时间范围从 618 年唐朝建立延伸至 1949 年近代史结束。
- 以唐、五代十国、宋、元、明、清、近代七个时代区间组织空间与视觉语言。
- 首批内置 30 个精选历史事件，兼顾政治、战争、制度、科技、文化与社会变革。
- 事件知名度采用五级影响力，直接控制光点大小、辉光、粒子密度和点击特效强度。
- 每个事件包含年份、标题、时代、人物、摘要、完整故事、主题色和空间偏移。
- 事件光点可以拖拽。拖拽只改变事件的纵深与垂直视觉位置，不改变其在时间轴上的年份和史实顺序。
- 点击事件后，镜头平滑聚焦，触发粒子爆发、环形冲击波和人物名浮现，同时打开故事面板。
- 用户可以关闭故事面板、选择其他事件、拖拽时间轴、使用滚轮航行、点击时代刻度跳转，并通过“归位”按钮回到全景。
- 移动端支持单指旋转视角、拖拽事件、横向浏览时间轴和点击详情；界面会缩减装饰而保留完整内容。

## 视觉方向

### 核心构图

主场景是一条略带弧度、从左下伸向右上深处的“星河年表”。时间轴并非普通直线，而是由青铜金属骨架、流动能量和细密年代刻度组成。事件光点像悬挂在历史引力场中的星体，围绕轴线缓慢漂移。远处以层叠的山河雾、星尘与抽象书页碎片建立中国历史的空间感。

### 色彩系统

- 墨夜 `#05070A`：场景底色与深空。
- 青瓷 `#79B7A7`：宋与知识文明相关事件。
- 青铜金 `#C7A35B`：时间轴、年代与核心照明。
- 朱砂 `#D64B36`：战争、变革与强交互反馈。
- 玉白 `#E8E2D1`：正文、人物名与高光。
- 靛青 `#355C7D`：雾层、近代与空间层次。

各时代获得独立的辅色和环境雾，但共享上述基础色，以保持统一宇宙观。页面避免单一蓝紫色科技风，也不使用装饰性渐变球体。

### 字体与排版

标题使用系统中文宋体栈营造碑刻与典籍感；正文与控件使用清晰的现代黑体栈；年份使用等宽字体。标题不做夸张大字海报，而是作为场景中的克制标识。所有字距为零。

### 标志性元素

作品的记忆点是“历史引力”：被选中的事件会吸引周围星尘形成旋涡，时间轴产生向外传播的金色冲击波，人物姓名像从尘埃中凝结出来，随后故事面板从场景边缘展开。

## 信息架构

### 顶层界面

- 左上：项目名称“历史星河”、当前时代与当前年份。
- 顶部中央：时代快速导航，使用紧凑的分段控件。
- 右上：音效开关、归位按钮、帮助按钮，均使用图标和悬浮提示。
- 中央：全屏 Three.js 场景。
- 底部：年代范围、拖动进度和当前附近事件的简短标签。
- 右侧：选中事件的故事面板；桌面宽度约 380px，移动端使用底部抽屉。
- 首次进入：以短暂的镜头推进和标题淡出完成开场，不弹出说明卡片。

### 故事面板

故事面板展示事件年份、事件名、所属时代、影响力、关键人物、约 120 至 220 字的故事，以及前后事件导航。人物以姓名印章形式出现，不依赖外部肖像资源，避免素材不一致和加载失败。

### 无障碍与降级

- 所有可点击事件在 DOM 中有对应的无障碍按钮和可读标签。
- 键盘用户可以按左右方向键切换事件，回车打开详情，Escape 关闭详情。
- `prefers-reduced-motion` 下减少镜头飞行、漂移和粒子爆发。
- WebGL 初始化失败时显示可浏览的二维事件列表，而不是空白画面。

## 技术架构

### 应用层

继续使用现有 Vite、React 19 和 TypeScript 工程。可见入口改为《历史星河》，但不删除当前工作区中的内容数据与文章组件文件。`App.tsx` 仅负责组合界面状态、场景和故事面板。

### 3D 层

使用 `three` 与 `@react-three/fiber` 构建场景，使用 `@react-three/drei` 提供相机控制与常用辅助能力，使用 `@react-three/postprocessing` 提供 Bloom 与轻量色彩处理。核心组件边界如下：

- `HistoryScene`：Canvas、相机、灯光、雾、后期处理和总体交互模式。
- `TimelineRail`：时代区段、年代刻度、能量流与时代跳转定位。
- `EventStar`：单个事件光点、拖拽、悬停、选中与无障碍镜像状态。
- `StarField`：确定性随机星尘、远景薄雾与书页碎片。
- `SelectionEffects`：点击后的粒子爆发、冲击波和人物姓名凝结动画。
- `StoryPanel`：独立于 Canvas 的语义化 DOM 叙事界面。

### 数据与状态

历史数据存放在单一 TypeScript 数据文件中，并通过纯函数完成年份到空间坐标、影响力到尺寸、时代到色彩的映射。应用状态只包含当前事件、悬停事件、当前时代、相机目标、故事面板状态和用户拖拽产生的视觉偏移。

事件拖拽偏移保存在会话内存中，刷新后恢复策展构图。这样既保持可玩性，也避免长期保存错误的历史空间关系。

### 动画与性能

- 所有环境粒子使用 `Points`、实例化几何体或着色器，避免逐粒子 React 组件。
- 事件数量固定且较少，每个事件使用独立交互对象和共享材质策略。
- 根据设备像素比限制渲染分辨率，移动端降低粒子数量和 Bloom 强度。
- 镜头、悬浮和选中特效在渲染循环中按时间插值，不通过 React 每帧更新状态。
- 页面离开或组件卸载时释放几何体、材质和事件监听器。

## 交互规则

1. 页面加载后，相机从时间轴远端推进到唐朝附近，并在约 2.5 秒内稳定为可交互状态。
2. 拖拽空白场景旋转视角，滚轮沿时间轴前后航行；移动端以单指拖动完成对应操作。
3. 悬停事件时显示年份和标题，光点提升亮度，但不移动相机。
4. 短按事件触发选择；拖动超过阈值后进入光点拖拽，松手不会误触发详情。
5. 选择事件时，相机聚焦至事件附近但保留时代上下文，随后打开故事面板。
6. 再次点击已选事件只重播一次轻量冲击波，不重复打开动画。
7. 点击时代导航将相机移动到该时代的代表年份，并自动选择该时代最重要的事件。
8. 用户可随时按 Escape 或点击关闭图标退出详情；相机保留当前位置。

## 响应式设计

- 大于 1024px：完整右侧故事面板、全部时代导航和高粒子密度。
- 640px 至 1024px：面板变窄、底部标签减少、保留时代导航。
- 小于 640px：故事改为底部抽屉，时代导航可横向滚动，项目标题缩为单行标识，辅助信息隐藏，3D 画布始终占满视口。
- 所有固定控件考虑安全区域，长事件名允许换行，不覆盖场景导航。

## 内容基线

精选事件至少包含：贞观之治、开元盛世、安史之乱、两税法、黄巢起义、陈桥兵变、澶渊之盟、王安石变法、靖康之变、岳飞抗金、蒙古崛起、元朝建立、行省制度、郑和下西洋、土木堡之变、张居正改革、万历援朝、明朝灭亡、康乾盛世、鸦片战争、太平天国、洋务运动、甲午战争、戊戌变法、义和团运动、辛亥革命、五四运动、北伐战争、抗日战争胜利和中华人民共和国成立。

内容采用简明、审慎的中文叙述，不对争议人物作单一价值判断；人物与故事只陈述能够由常识性史料支持的事实关系。

## 测试与验收

### 自动化

- 数据测试覆盖事件年份排序、时代边界、唯一 ID、必填字段和影响力范围。
- 映射函数测试覆盖年份到坐标、影响力到尺寸、拖拽阈值和时代定位。
- React 测试覆盖项目名称、时代导航、事件选择、故事面板打开关闭、键盘切换和二维降级内容。
- `npm test` 与 `npm run build` 必须通过。

### 真实浏览器

- 使用 Playwright 在 1440×900、1280×720 和 390×844 三个视口验收。
- 对 Canvas 执行像素检查，确认不是空白、全黑或单色画面。
- 截图检查标题、导航、时间轴、事件光点和故事面板无重叠。
- 验证时代跳转、空白拖拽、滚轮航行、事件拖拽、事件点击、关闭详情和键盘操作。
- 检查浏览器控制台无未处理异常、资源 404 和持续 WebGL 警告。

## 交付标准

- 开发服务器启动后，用户打开根 URL 即进入《历史星河》。
- 首屏可见真实渲染的 3D 时间轴、多个不同大小的事件光点和时代标识。
- 用户无需阅读说明即可进行航行、拖拽、点击与故事浏览。
- 唐至近代的主要事件可访问，人物与故事内容完整。
- 桌面与移动端均无关键内容遮挡，Canvas 非空且交互稳定。
- 现有未提交工作不会被回滚或混入本功能的独立规格提交。
