# 历史星河全维度历史百科设计

## 目标

将现有《历史星河》从 30 个代表事件的 3D 时间轴，扩展为覆盖先秦至 1949 年的全维度中国历史探索系统。

最终版本收录约 815–1095 个主事件，并通过子事件继续展开战役阶段、改革措施和人物行动。内容覆盖政治、战争、制度、经济、科技、文化、思想、宗教、外交、民族关系和社会生活。每个事件具备结构化历史档案，每个重要人物拥有独立人物百科，所有档案提供可追溯的参考资料。

核心体验必须同时满足：

- 在全景中看见历史结构，而不是被上千个光点淹没。
- 通过缩放逐层展开朝代、时期、主题、事件和子事件。
- 通过搜索、筛选和专题路线快速找到具体内容。
- 点击光点后保持 3D 探索连续性，同时可以进入完整档案深度阅读。
- 在桌面、移动端和无 WebGL 环境中均可使用。
- 保持纯静态部署，不增加数据库或内容管理服务器。

## 当前状态

现有版本覆盖唐朝至 1949 年，共 30 个事件，其中唐朝 5 个。事件模型只有标题、年代、朝代、影响力、人物姓名、摘要和单段故事。所有事件同时渲染并列入一个平铺导航列表，适合演示，但不能承载数百事件、人物档案、全文检索和深度内容。

本次扩展需要重构历史数据层、空间可视化层、检索层和档案阅读层；不能通过继续扩充单个 `events.ts` 文件完成。

## 内容范围

### 时间边界

覆盖先秦至 1949 年，包括：

- 传说时代与早期国家形成
- 夏商周、春秋战国
- 秦汉
- 三国、两晋、南北朝
- 隋唐
- 五代十国、宋辽金夏
- 元
- 明
- 清
- 1840–1949 年近代史

公元前年份使用负数进行排序，展示时转换为“公元前”。无法精确到单年的事件允许使用年代范围和模糊标记，例如“约公元前 1600 年”“8 世纪中期”。

### 叙事标准

采用通俗主流历史叙事，优先与统编历史教材和常见权威通史保持一致。对于夏商周、古史传说、人物生卒、事件时间或历史评价中存在的明显争议，正文保持清晰连贯，并增加简短“史学说明”，不把争议结论写成确定事实。

### 事件规模

| 历史阶段 | 主事件目标 |
| --- | ---: |
| 先秦 | 100–130 |
| 秦汉 | 90–120 |
| 魏晋南北朝 | 80–110 |
| 隋唐 | 120–160 |
| 五代、宋辽金夏 | 120–160 |
| 元 | 45–65 |
| 明 | 75–105 |
| 清前中期 | 75–100 |
| 近代 1840–1949 | 110–145 |

预计建设 1500–2500 个人物档案。主时间轴只收录能够解释时代变化或具有代表性的事件；具体战役阶段、改革条目和人物行动作为子事件展开，避免用大量微小条目稀释历史脉络。

## 技术架构

### 静态内容仓库

历史内容使用版本化 JSON 与 Markdown Frontmatter 文件管理，随 Git 审查和发布。历史阶段、主题、来源和紧凑索引使用 JSON；事件与人物档案使用带严格 Frontmatter 的 Markdown。构建脚本校验并编译为按时代拆分的静态 JSON。核心代码与内容分离：

```text
src/history/
  manifest/
    eras.json
    themes.json
    sources.json
  indexes/
    events.compact.json
    people.compact.json
    places.compact.json
  content/
    pre-qin/
      events/*.md
      people/*.md
    qin-han/
    wei-jin/
    sui-tang/
    song-liao-jin-xia/
    yuan/
    ming/
    qing/
    modern/
  schemas/
  validation/
```

首屏只加载紧凑索引，包含事件 ID、年代、标题、阶段、主题、影响力、人物 ID、地点 ID 和空间元数据。完整正文按历史阶段动态加载。事件档案、人物档案和专题路线复用同一实体关系，不复制正文。

### 加载策略

- 首屏加载历史阶段清单、紧凑事件索引和 3D 场景必要数据。
- 搜索索引在 Web Worker 中异步初始化，不阻塞场景首帧。
- 点击事件或进入一个时代时加载对应内容分包。
- 已加载分包保存在内存缓存中；浏览器可以通过标准 HTTP 缓存复用静态文件。
- 单个分包失败只影响该历史阶段，界面显示中文错误和重试入口。
- 搜索 Worker 失败时降级为标题、人物名称和别名的前缀搜索。

### 搜索技术

使用 MiniSearch 为事件、人物、地点、别名、主题和摘要建立客户端全文索引。中文字段在构建阶段生成字符 n-gram 和规范化别名，解决无空格文本和古今名称问题。

## 数据模型

### 历史事件

事件至少包含：

- 稳定 ID、标题、别名
- 起止年代、年代精度和展示文本
- 历史阶段、政权和具体时期
- 事件类别与专题标签
- 影响力等级 1–5
- 150–250 字快速摘要
- 历史背景
- 直接原因与深层原因
- 发展过程与关键节点
- 结果与后续变化
- 政治、经济、社会、文化等维度影响
- 核心人物、地点和涉及区域
- 父事件与子事件
- 前因、后续、并行和对比事件
- 史学说明
- 参考资料 ID
- 3D 布局提示与手动拖动偏移

### 人物档案

人物至少包含：

- 稳定 ID、姓名、字号、庙号、谥号和常见别名
- 生卒年代、年代精度、籍贯和主要活动区域
- 身份及其随时间的变化
- 300–500 字人物概述
- 生平时间线
- 政治主张、思想、作品或主要贡献
- 盟友、对手、君臣、师友和亲属关系
- 参与事件
- 历史评价与后世影响
- 相关作品、制度、遗迹和参考资料

人物与事件关系双向生成和校验。人物档案不重复保存事件正文，只引用事件 ID。

### 地点、专题与来源

- 地点保存古今名称、历史时期名称、地理坐标和相关事件。
- 专题保存有顺序的事件路线、章节说明和推荐镜头。
- 来源使用统一目录保存作者、书名或机构、版本、章节、链接、访问日期和适用条目。
- 每个事件至少关联 1–3 条参考资料，每个人物至少关联一条传记或权威资料。

## B+C 混合可视化

### 语义层级缩放

镜头距离决定显示的信息层级：

| 层级 | 可见内容 |
| --- | --- |
| 中国史全景 | 历史阶段、30–50 个关键事件、朝代或时期事件簇 |
| 朝代视图 | 重要事件、阶段分段和主题事件簇 |
| 时期视图 | 当前时期全部主事件、分类颜色和主要关系线 |
| 事件近景 | 单个事件、子事件、人物、地点和前因后果网络 |

影响力 5 级的重大事件恒常可见。当前选中事件和搜索定位事件永远不会被聚类隐藏。

### 屏幕空间动态聚类

事件首先按历史时期和主题形成候选组，再按照投影后的屏幕距离聚合。聚类半径使用像素而非世界坐标，使桌面、移动端和不同镜头角度下都能稳定控制密度。

使用 `d3-quadtree` 计算屏幕空间邻近事件。聚类计算在 Web Worker 中执行，并采用缩放迟滞区间，避免镜头停在临界位置时事件簇反复闪烁和拆分。

点击事件簇后镜头自动拉近到其包围范围，事件簇逐级拆分。点击空白、面包屑或返回按钮逐级回退。

### 渲染性能

- 使用 Three.js `InstancedMesh` 或 GPU Points 批量绘制光点。
- 视锥外事件不参与标签、聚类和交互计算。
- 标签使用独立碰撞检测，仅显示不重叠的高优先级标题。
- 关系线只在近景、专题路线或选中事件后显示。
- 移动端降低粒子、辉光、标签和关系线预算。
- 桌面目标接近 60 FPS，移动端目标不低于 30 FPS。

### 操作方式

- 滚轮、触控板和双指缩放。
- 点击事件簇自动拉近并拆分。
- 双击朝代或时期进入对应视域。
- 搜索结果直接飞行定位到事件。
- 拖动事件光点产生空间偏移并展开关系线；松开后可回弹或固定位置。
- 界面始终显示当前缩放层级、历史范围和返回路径。
- 用户镜头、筛选、拖动偏移和阅读位置保存在本地。

## 事件与人物阅读体验

### 快速侧栏

点击光点后在 3D 场景上方打开快速侧栏，包含：

- 年代、事件名称、历史阶段和影响力
- 150–250 字摘要
- 主要起因、结果和历史影响
- 3–6 位核心人物
- 前因、后续和同一时期事件
- 上一个、下一个事件
- 进入完整档案按钮

侧栏保持当前镜头和场景交互状态。

### 完整事件档案

每个事件使用独立 Hash URL `#/history-galaxy/event/<event-id>`，支持刷新、分享和浏览器返回。统一章节为：事件概览、历史背景、原因、发展过程、结果、影响、人物、地点、关系图、史学说明和参考资料。

从档案返回星河时恢复原镜头、缩放、筛选和选中事件。

### 独立人物百科

人物姓名可进入独立 Hash URL `#/history-galaxy/person/<person-id>`。档案显示人物概述、生平时间线、身份变化、主张或贡献、人物关系、参与事件、历史评价、作品或遗迹以及参考资料。专题使用 `#/history-galaxy/theme/<theme-id>`。

搜索词和筛选状态使用 URL 查询参数表达，可分享同一搜索结果。镜头矩阵和临时拖动偏移只保存在浏览器本地，不写入分享 URL。

事件、人物、地点和专题之间保持双向导航。

## 搜索、筛选与专题路线

### 历史探索器

桌面使用可收起侧栏，移动端使用底部抽屉。提供：

- 事件、人物、地点的全文搜索
- 历史阶段、朝代、时期和政权筛选
- 政治、战争、制度、经济、科技、文化、思想、宗教、外交、民族关系和社会生活筛选
- 人物、地点、专题、影响力和年代范围筛选
- 只看重大事件开关
- 只看当前镜头范围开关

筛选不会从空间中删除非匹配事件，而是降低其亮度并重新计算聚类，使搜索结果仍保留历史上下文。

### 专题路线

首批专题包括：

- 中国统一与分裂
- 中央集权制度演变
- 土地与赋税制度
- 科举与官僚体系
- 丝绸之路与中外交流
- 北方民族与中原王朝
- 中国古代科技发展
- 儒释道思想演变
- 文学艺术发展
- 近代化与民族危机

专题按事件顺序驱动镜头旅行，用户可随时暂停、自由旋转或退出。

## 无障碍与降级

- 所有光点、事件簇、筛选项和档案导航都有中文可访问名称。
- 键盘可以完成搜索、筛选、事件选择、前后切换和返回。
- 遵循 `prefers-reduced-motion`，关闭自动飞行和强烈粒子动画。
- WebGL 不可用或场景初始化失败时进入完整二维时间轴，继续提供搜索、筛选、事件侧栏和完整档案。
- 颜色之外同时使用形状、图标、文字和数值表达类别与影响力。

## 内容生产与质量控制

内容流水线为：

```text
事件目录编制
  → 资料来源登记
  → 结构化初稿
  → 年代、人物、地点与关系校验
  → 中文可读性整理
  → Schema 检查
  → 抽样复核
  → 合并和发布
```

资料优先使用统编历史教材、中华书局史书整理本、权威通史和专题史，并辅以国家博物馆、故宫博物院、国家文物局、大学和研究机构公开资料。不使用无法确认出处的自媒体内容，不编造古人原话。

构建阶段必须验证：

- 所有 ID 唯一且引用存在。
- 事件、人物和地点关系双向一致。
- 年代与对应历史阶段一致，公元前排序正确。
- 每个完整事件具有背景、过程、结果、影响和来源。
- 每个人物至少关联一个事件。
- 同一史实不会因别名重复收录。
- 主事件与子事件不存在循环引用。
- 搜索索引包含别名、古今地名、字号、庙号和谥号。
- 失效人物、关系或参考资料直接阻止构建发布。
- Markdown 正文禁止原始 HTML；外部参考链接只允许 `https:`，并在渲染层统一添加安全的外链属性。

## 测试与验收

### 数据测试

- Schema、唯一性、引用完整性和双向关系。
- 年代范围、模糊年代和公元前排序。
- 事件与人物最低内容完整度。
- 来源数量与来源目录引用。
- 主题路线顺序与循环检测。

### 可视化测试

- 1200 个事件下聚类数量和拆分结果正确。
- 缩放临界点无明显闪烁。
- 重大事件和当前选中事件不被隐藏。
- 标签不遮挡关键控件或相互大面积重叠。
- 搜索定位和返回镜头状态正确。
- 桌面、移动端帧率与内存预算。

### 功能测试

- 搜索、组合筛选、重大事件开关和镜头范围筛选。
- 事件侧栏、完整档案、人物档案和双向关系导航。
- 档案 URL 刷新、分享和浏览器返回。
- 专题路线播放、暂停和退出。
- Web Worker 失败、分包加载失败和无 WebGL 降级。
- 键盘、触控、滚轮和减少动态效果模式。

## 分阶段交付

### 第一阶段：星河引擎升级

完成数据 Schema、紧凑索引、按需加载、语义缩放、动态聚类、全文搜索、档案路由和性能框架，并用跨时代代表事件验证。

### 第二阶段：先秦至隋唐

完成先秦、秦汉、魏晋南北朝和隋唐内容。唐朝作为内容密度标杆，完整覆盖各类历史主题。

### 第三阶段：五代至清代

完成五代十国、宋辽金夏、元明清以及相关制度、文化和社会专题。

### 第四阶段：近代史与总体验收

完成 1840–1949 年、人物关系和专题路线，进行引用审查、内容抽查、移动端和性能验收。

每一阶段均可生成在线预览，但最终发布必须完成全部阶段和总内容审查。

## 非目标

- 不建设用户账户、评论、协作编辑和内容管理后台。
- 不在运行时调用生成式 AI 编写历史内容。
- 不依赖数据库或长期运行的后端服务。
- 不把传说和有争议推断伪装成确定史实。
- 不追求收录每一次官员任免、地方冲突或所有历史人物；通过主事件与子事件层级保持完整性和可读性。
